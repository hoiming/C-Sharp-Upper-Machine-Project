Day 1：搭骨架 + 协议帧定义

目标：通信核心项目建好，Frame 能按一份明确、可测试的协议编码成字节数组。

做什么：

    建解决方案 EnvMonitor，统一目标框架为 .NET 8，建五个项目：

        EnvMonitor.Protocol（类库）

        EnvMonitor.Communication（类库，TCP 客户端、DeviceService 与接口）

        EnvMonitor.Simulator（控制台）

        EnvMonitor.App（WPF）

        EnvMonitor.Tests（xUnit）

    项目引用关系：Simulator、Communication、Tests 引用 Protocol；App、Tests 引用 Communication。

    在 Protocol 里定义帧格式：

    | 0xAA55 | 总长2B | Cmd1B | Seq2B | Payload NB | CRC16 2B |

    固定协议契约：

        总长为从帧头到 CRC 的总字节数，最小 9，最大 1024；总长和 Seq 均为大端序。

        CRC16 覆盖从帧头第一个字节到 Payload 最后一个字节，不包含 CRC 本身。

        CRC 使用 Modbus 算法，写入顺序为低字节在前、高字节在后；这是大端序规则的唯一例外。

        正常响应复用请求的 Cmd 和 Seq；错误响应 Cmd = 请求 Cmd | 0x80，Payload = ErrorCode 1B。

    写 Frame.Encode() 和 Frame.Decode()，禁止将数组直接暴露为可修改的内部状态。

    写 Crc16.Compute()（Modbus CRC，多项式 0xA001）。

    定义命令表和 Payload：

        0x01 Read：请求为空；响应为 Temp(Int16 BE, /10)、Humidity(UInt16 BE, /10)、Pressure(UInt16 BE, /10)、Relay(Byte)，共 7B。

        0x02 SetRelay：请求与响应均为 Channel(Byte, 当前只允许 1)、On(Byte, 0 或 1)，共 2B。

        0x03 Heartbeat：请求和响应均为空。

        ErrorCode：0x01 非法命令，0x02 非法 Payload，0x03 非法继电器通道。

验收：

    写一个测试：构造 Cmd=0x01, Seq=1, Payload=空，编码后长度 = 9，且总长、Seq、CRC 字节顺序正确。

    写 CRC 标准向量测试：ASCII "123456789" 的 Modbus CRC = 0x4B37；再手动算一帧 CRC，和代码结果一致。

坑：

    长度字段算的是"从帧头到 CRC 的总字节数"，别只算 Payload。

    CRC 低字节在前，高字节在后。

Day 2：拆包器 + 单元测试

目标：粘包、半包、CRC 错和损坏长度都能正确处理并恢复同步。

做什么：

    写 FrameParser.Feed(byte[])，返回 IEnumerable<Frame>。

    处理逻辑：

        找 0xAA 0x55 帧头，前面垃圾丢弃

        长度不合法（<9 或 >1024）丢弃 1 字节重找

        数据不够时保留从候选帧头开始的所有字节，等下次 Feed

        CRC 校验失败只丢弃候选帧头的第一个字节，然后继续找帧头；不得丢弃整段缓存

    写测试用例：

        一次 Feed 完整一帧 → 出 1 帧

        一帧分两次 Feed → 第二次才出帧

        两帧粘在一起 → 出 2 帧

        CRC 错 → 不出帧

        前面有垃圾字节 → 能跳过

        CRC 错帧后紧跟合法帧 → 能恢复并产出合法帧

        非法长度后紧跟合法帧、帧头被分成两次 Feed → 都能恢复

验收：上述 7 个测试全绿。

坑：

    List<byte> 频繁 RemoveRange(0, n) 性能差，但学习阶段无所谓。

    循环里 yield return 和 yield break 别写错，否则会死循环。

Day 3：模拟下位机 TCP 服务

目标：模拟器能启动、接受连接、按命令表回复，并可被集成测试可靠地启停。

做什么：

    TcpListener 默认监听 127.0.0.1:9000；测试时允许传入端口 0，并公开实际绑定端口。

    每个客户端一个 Task，每个连接独享 FrameParser；VirtualDevice 的共享状态访问必须同步。

    读字节 → FrameParser.Feed → 对每个 Frame 调 VirtualDevice.Handle → 回写 resp.Encode()。

    VirtualDevice 先支持 Cmd=0x01，返回命令表规定的 7B 传感器 Payload，温度固定为 25.0，其余字段使用固定合法值。

    Payload 编码：温度 short = 250，大端写入 2 字节。

验收：

    模拟器启动，控制台打印"监听 9000"。

    模拟器提供 StartAsync/StopAsync(CancellationToken)；用 EnvMonitor.Tests 写集成测试：端口 0 起模拟器 → TcpClient 连上 → 发一帧 → 校验响应 → finally 停止模拟器。

坑：

    TcpListener 要 Start() 后才 AcceptTcpClientAsync()。

    NetworkStream.ReadAsync 返回 0 表示对端关闭，要 break。

Day 4：虚拟设备数据 + 故障注入

目标：数据会波动，故障可按概率或按固定次数复现，便于自动化验证。

做什么：

    VirtualDevice 加温度/湿度/压力，每次 Handle 时随机小幅波动。

    支持 Cmd=0x02 写继电器、Cmd=0x03 心跳。

    加故障注入开关（用命令行参数或控制台按键）：

        --drop 30：30% 概率不回复

        --delay 2000：延迟 2 秒回复

        --close-after 10：10 秒后断开

        --crc-error 3：第 3 个响应故意损坏 CRC

        --fragment：每帧拆成两次 WriteAsync

        --coalesce：将连续两个响应合并为一次写入

    为测试提供等价的强类型 FaultOptions（可指定第 N 帧故障）；命令行参数仅作为演示入口。

    控制台打印每次收到和发出的帧，方便调试；日志中标明是否注入了故障。

验收：

    连续发 10 次读命令，能看到温度小幅变化。

    开 --drop 30，上位机测试客户端会超时。

坑：

    随机数用 Random.Shared（.NET 6+）避免锁。

    延迟用 await Task.Delay，别用 Thread.Sleep 阻塞。

Day 5：上位机 TCP 客户端

目标：能安全地连接、并发发请求、收响应、超时和断线清理。

做什么：

    EnvMonitor.Communication 建 IFrameClient 和 TcpClientService.cs；App 只依赖接口，不直接操作 Frame。

    字段：TcpClient、NetworkStream、FrameParser、ConcurrentDictionary<ushort, TaskCompletionSource<Frame>>、_seq、写入 SemaphoreSlim、连接 CancellationTokenSource。

    ConnectAsync(host, port)：连接 + 启动接收循环。

    ReceiveLoop：读 → Feed → 按 Seq 匹配 TCS。

    SendAsync(cmd, payload, timeoutMs)：

        原子生成未被占用的 Seq，注册带 RunContinuationsAsynchronously 的 TCS

        获取写锁后写流，finally 释放写锁

        Task.WhenAny(tcs.Task, Task.Delay(timeout, cancellationToken))

        超时、取消或写入失败时从字典移除 TCS；超时抛 TimeoutException

    Disconnect()：取消 CTS，关闭连接，并用 ObjectDisposedException 或 IOException 完成所有未决 TCS。

    收到错误响应时按 Seq 完成对应 TCS，并由业务层转换为有意义的异常；无法匹配 Seq 的帧触发 UnsolicitedFrame。

验收：

    控制台或临时按钮调用 ConnectAsync + SendAsync(0x01)，能拿到响应。

    并发发多个请求时响应均能按 Seq 匹配；模拟器开 --drop，SendAsync 抛超时且 Pending 数量回到 0。

坑：

    TaskCompletionSource 要用 RunContinuationsAsynchronously，否则可能死锁。

    接收循环异常要 catch，否则 Task 静默死掉。

Git：feat: 上位机 TCP 客户端与超时
Day 6：自动重连 + 连接状态

目标：意外断线后自动重连，手动断开不重连，UI 能感知状态。

做什么：

    TcpClientService 保存目标 host/port，加 event Action<ConnectionState> ConnectionChanged；状态至少包括 Connecting、Connected、Disconnected、Reconnecting。

    接收循环结束或异常时触发 ConnectionChanged(ConnectionState.Disconnected)。

    仅由意外断线启动唯一的自动重连循环：指数退避 1s、2s、4s、8s、最大 30s；手动 Disconnect 会取消该循环。

    加 event Action<Frame> UnsolicitedFrame，为以后主动上报留口子。

验收：

    模拟器 --close-after 10，10 秒后上位机状态变为 Disconnected，然后自动重连成功。

    日志能看到重连间隔递增。

坑：

    重连要用新的 TcpClient，旧的 Close() 掉；重连成功后退避间隔重置。

    每次新连接使用新的 CTS，别复用已 cancel 的；事件在后台线程触发，WPF 层必须通过 Dispatcher 更新绑定属性。

Day 7：业务服务层

目标：UI 不直接碰 Frame，只碰强类型。

做什么：

    定义 record SensorData(double Temp, double Humidity, double Pressure, byte Relay) 和 IDeviceService。

    DeviceService：

        ReadAsync() → 发 0x01，解析 Payload 成 SensorData

        SetRelayAsync(ch, on) → 发 0x02

        HeartbeatAsync() → 发 0x03

    解析注意：short 大端，/10.0 还原。

    在 EnvMonitor.Tests 里用 IFrameClient 假实现测 DeviceService 的正常、错误响应和错误 Payload；模拟器集成测试只覆盖端到端协议。

验收：

    集成测试：连模拟器 → ReadAsync → 温度在 20-30 之间。

    SetRelayAsync(1, true) 后再 ReadAsync，Relay 字段为 1。

坑：

    (short)((p[0] << 8) | p[1]) 要先转 short 再除，别先除。

    Payload 长度要校验，防止越界。

Day 9：轮询 + 数据刷新

目标：每秒读一次，UI 实时更新。

做什么：

    MainViewModel 加 DispatcherTimer，间隔 1 秒。

    Tick 里 await _dev.ReadAsync()，赋值给属性。

    连接成功启动 timer，断开停止。

    异常处理：

        TimeoutException → Status = "读取超时"

        其他异常 → Status = 异常消息

    继电器命令：先改 UI，失败回滚。

验收：

    连接后温度每秒变化。

    模拟器 --drop 30，UI 偶尔显示"读取超时"，不崩溃。

    点继电器，模拟器状态跟着变。

坑：

    DispatcherTimer 的 Tick 是 async void，异常要 try-catch 全包。

    轮询没结束就下一次 Tick 会重入，加个 _isPolling 标志。

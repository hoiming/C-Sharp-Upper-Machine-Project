2. 系统目标

系统模拟一个环境传感器下位机，通过 TCP 让 WPF 上位机完成连接、命令交互、数据刷新和异常处理。

  1. 建立 TCP 连接。
  2. 发送读取、继电器和心跳命令。
  3. 接收并解析二进制帧。
  4. 处理半包、粘包、CRC 错误、超时和断线。
  5. 以 MVVM 方式显示传感器数据。
  6. 对温度、湿度超阈值进行状态报警。
  7. 显示最近两分钟温度曲线。

5. 协议详细设计

偏移       长度       字段
0          1          Header1 = 0xAA
1          1          Header2 = 0x55
2          2          Length，大端序
4          1          Command
5          2          Sequence，大端序
7          N          Payload
7 + N      2          CRC16，低字节在前
  • 总长范围为 9 到 1024。
  • CRC 覆盖 Header 到 Payload，不包含 CRC 本身。
  • CRC 使用 Modbus 算法，初始值 0xFFFF，多项式 0xA001。
  • 正常响应复用请求 Command 和 Sequence。
  • 错误响应 Command 为请求 Command 按位或 0x80，Payload 为 1 字节 ErrorCode。

空读帧固定测试向量：

AA 55 00 09 01 00 01 8E 93
命令 请求 Payload 成功响应 Payload
0x01 Read 空 Temp Int16 BE、Humidity UInt16 BE、Pressure UInt16 BE，均除以 10，加 Relay Byte，共 7B
0x02 SetRelay Channel Byte、On Byte Channel Byte、On Byte
0x03 Heartbeat 空 空

错误码：0x01 非法命令，0x02 非法 Payload，0x03 非法继电器通道。

6. 帧拆包设计

FrameParser 使用 List<byte> 缓存。Feed 流程是：追加数据、搜索 AA 55、丢弃前置垃圾、读取长度、等待完整帧、调用 Frame.Decode、成功后移除完整帧，失败时只丢弃一个候选帧头字节。

因此支持帧头拆分、完整帧拆分、多帧合并、CRC 错帧后恢复和非法长度后恢复。当前实现适合学习和演示，高吞吐场景可替换为环形缓冲区或 PipeReader。

7. 模拟器设计

7.1 生命周期

StartAsync() 创建 Loopback TcpListener；端口 0 由系统分配并暴露实际端口。每个客户端拥有独立 FrameParser 和处理任务。StopAsync() 取消服务器 CTS、停止 Listener、关闭客户端并等待 Accept 循环。

7.2 虚拟设备

VirtualDevice 在锁内处理请求，维护温度、湿度、压力和继电器状态。传感器初始值约为 25.0°C、48.0%、101.3kPa；Read 命令使用 Random.Shared 做小幅波动；继电器当前只支持 Channel 1。

7.3 故障注入

选项 行为
DropProbabilityPercent 按概率不回复。
ResponseDelay 异步延迟响应。
CloseAfter 连接建立后定时关闭。
CrcErrorResponseNumber 指定响应损坏 CRC。
FragmentResponses 一帧拆成两次写入。
CoalesceResponses 同一批次多帧合并写入。

8. 上位机通信设计

8.1 请求发送

SendAsync() 原子生成 Seq，创建带 RunContinuationsAsynchronously 的 TCS，放入 Pending 字典；使用 SemaphoreSlim 串行写流；等待响应或超时；在超时、取消或写失败时清理 Pending。

8.2 接收循环

NetworkStream 的每次读取都送入 FrameParser。Seq 匹配 Pending 时完成对应 TCS，否则触发 UnsolicitedFrame。CRC 错误由解析器丢弃，原请求最终超时。读到 0 或异常会完成未决请求并进入断线处理。

8.3 状态与重连

连接状态包括 Connecting、Connected、Disconnected、Reconnecting。意外断线启动唯一重连循环，等待 1、2、4、8 秒，最大 30 秒；重连使用新的 TcpClient、Stream 和 CTS。手动 DisconnectAsync 会取消重连并完成未决请求。

9. 业务服务设计

DeviceService 隔离 Frame 细节：ReadAsync 要求 7 字节并进行大端缩放；SetRelayAsync 检查 Channel 和状态回显；HeartbeatAsync 要求空响应。错误响应转换为 InvalidOperationException，非法长度或字段转换为 InvalidDataException。

10. WPF 与 MVVM

App 启动时加载 appsettings.json、校验配置、初始化 Serilog，并组装 TcpClientService、DeviceService、MainViewModel。MainWindow 只通过 DataContext 绑定 ViewModel。

MainViewModel 暴露状态、连接按钮、温湿压、继电器、报警状态、曲线数据以及 Connect、Reconnect、ToggleRelay 命令。DispatcherTimer 按配置周期轮询，使用 _isPolling 防止重入；断开时停止 Timer 并清空曲线。

温度超过配置阈值 30、湿度超过 70 时状态变为 Alarm，XAML DataTrigger 将对应数值变红；读取超时显示黄色状态。曲线保留最近 120 个 DateTimePoint。

14. 已知限制与风险

发布前需要关注：LiveCharts 依赖链存在 NU1701；发布前应确认目标机器运行时兼容性，或升级/替换图表包。
  • FrameParser 使用 List<byte>，高吞吐场景会有额外复制。
  • TCP 客户端没有 TLS、认证或设备身份校验。
  • WPF ViewModel 没有独立测试项目，主要依靠集成测试和构建验证。
  • 日志使用 App 层 Serilog，Communication 层没有独立 ILogger 抽象。
  • 模拟器随机波动只用于演示，不代表真实传感器噪声。
